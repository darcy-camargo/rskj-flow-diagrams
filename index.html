How blocks and transactions move through RSKJ

Every function a block passes through in the Rootstock node, from the moment it arrives until it is executed, stored and persisted, and the path a transaction takes into the mempool. Zones show what has been checked so far; each box links to its source line.

Source: rsksmart/rskj, commit 1e95a3b (October 16, 2026), default configuration.

Status zones (block diagrams)

  • Received, not validated

  • Fully validated

  • Connected and stored
  • After connection: listeners
  • Persisted: storage layer

Boxes

  • Entry point: where a path starts or block data arrives
  • Function. Hover for what it does, click to open its line on GitHub.
  • Class: functions of the same class. Hover its border area for a summary.
  • Interface, with the implementations used
  • Branch inside the calling function
  • Joins the main path (click to jump)

Arrows

  • Direct call
  • Hand-off: queue, thread or network round trip
  • Call through the other implementation
  • Listener callback
